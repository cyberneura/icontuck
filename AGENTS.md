# Icontuck — notes for agents

See README.md for build, usage, and release steps. This is a public repository, so the README, this file, UI strings, and code comments are written in English.

## Third-party license notices

- `THIRD-PARTY-NOTICES.txt` and `Icontuck/ThirdPartyNotices.swift` are generated by `scripts/generate-third-party-notices.sh`. Do not edit them by hand.
- When adding or upgrading a dependency, rerun `./scripts/generate-third-party-notices.sh` and commit the result. The PR Test workflow detects stale output with `--check`.
- Currently only Apple system frameworks are used, and no third-party libraries are bundled. Adding a Swift Package makes the script stop with an error, so extend the script to include each package's LICENSE from the pins in `Package.resolved` (it is fine to assume resolving happens on macOS). Check with a human before adding any dependency under a GPL / LGPL / AGPL-family license.
- In the app, the notices are shown via "Third-Party Licenses…" in the status item's right-click menu (`AppDelegate.showThirdPartyLicenses`).

## Other

- `Icontuck.xcodeproj/project.pbxproj` does not use file-synchronized groups. When adding a Swift file, register it in 4 places: PBXBuildFile / PBXFileReference / the group's children / the Sources build phase.
- Swift compilation is checked by this repository's PR Test workflow (macOS, unsigned Debug build).
- The version is normally bumped by `./scripts/release.sh [patch|minor|major]` (it pushes directly to main and triggers the Release workflow). If a feature PR bumps `MARKETING_VERSION` (bump `CURRENT_PROJECT_VERSION` by 1 as well), then after merging, do not use release.sh; trigger the Release workflow directly with `gh workflow run release.yml --ref main`. release.sh always cuts "the next number", so the number bumped in the PR would be skipped without ever being published.
